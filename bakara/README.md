# מערכת בקרה למנהל תורן

מערכת לבקרה על הצרכים הבסיסיים של כל ילד בפנימייה, לאורך כל היום. מיועדת למנהל התורן ולמנהל הכפר.
כל הנתונים במערכת הם נתוני דמה.

## פריסה לאינטרנט (Render)

בשורש המאגר יש קובץ `render.yaml` שמקים אוטומטית את האתר ואת בסיס הנתונים. בבנייה הראשונה נטענים נתוני דמה, ובעדכונים הבאים הנתונים נשמרים.

1. נכנסים ל-https://render.com ונרשמים עם חשבון GitHub.
2. לוחצים New ואז Blueprint.
3. בוחרים את המאגר TOKAYER-SIKUM-YOM ואת הענף שבו נמצאת המערכת, ולוחצים Apply.
4. אחרי כמה דקות מופיע קישור בסגנון `https://bakara-xxxx.onrender.com`.

בתוכנית החינמית האתר נרדם אחרי 15 דקות בלי שימוש, והכניסה הראשונה אחרי זה לוקחת כדקה. בסיס הנתונים החינמי של Render נמחק אחרי 30 יום. לשימוש קבוע עוברים לתוכנית בתשלום או ל-Supabase.

כשנתוני הדמה מתיישנים: נכנסים כ-admin, עוברים ל"משתמשים", ולמטה לוחצים "טעינה מחדש של נתוני הדמה".

## הפעלה על מחשב מקומי

צריך Node.js בגרסה 20 ומעלה ו-PostgreSQL.

```bash
cd bakara
cp .env.example .env      # ולעדכן בו את DATABASE_URL
npm install
npm run setup             # יוצר את הטבלאות וטוען נתוני דמה
npm run dev
```

פותחים בדפדפן: http://localhost:3000

## מעבר לנתונים אמיתיים

1. **משתמשים:** נכנסים כ-admin, עוברים ל"משתמשים", ומחליפים סיסמה לכל משתמש. משתמש שלא צריך, מבטלים לו את הסימון "פעיל". כל עוד יש משתמש עם סיסמת הדמה, הייבוא חסום.
2. **ייבוא:** ב"ילדים" לוחצים "ייבוא מאקסל" ובוחרים את הקובץ. מ-Google Sheets מורידים אותו דרך קובץ > הורדה > Microsoft Excel. המערכת מזהה לבד את העמודות (שם, ביתן, גיל או תאריך לידה, תרופות, שעת שינה, הערות). כשכל ביתן נמצא בגיליון נפרד, שם הביתן נלקח משם הגיליון.
3. **אחרי הייבוא:** המערכת עוברת למצב אמיתי. הכפתור לטעינת דמה נעלם, ופרטי הדמה לא מוצגים יותר במסך הכניסה.

הקובץ נקרא בדפדפן ונשמר ישירות בבסיס הנתונים. שמות הילדים לא נשמרים בקוד וב-GitHub.

## מבנה

- `prisma/schema.prisma`: מבנה הנתונים
- `src/lib/demo-seed.ts`: נתוני הדמה
- `src/lib/checks.ts`: תחומי הבקרה, נקודות הזמן ושעות היעד. כאן משנים שעות או מוסיפים תחום
- `src/lib/engine.ts`: חישוב הצבעים, מה חסר לפי השעה, מה חוסם סגירת משמרת ותמונת המצב למנהל
- `src/app`: המסכים ופעולות השרת

## אבטחה: מה קיים ומה נשאר

קיים: כניסה אישית עם סיסמה מוצפנת (bcrypt), הרשאות לפי תפקיד שנבדקות בשרת בכל עמוד ופעולה, יציאה אוטומטית אחרי 30 דקות בלי פעילות, יומן פעולות (Audit Log) לכל שינוי כולל ערך קודם וחדש, ניהול משתמשים.

לפני שימוש במידע אמיתי חובה: העלאה לשרת עם HTTPS, מעבר ל-Postgres מנוהל (למשל Supabase) עם הצפנה וגיבוי, מדיניות סיסמאות, ובדיקה של יועץ אבטחת מידע.

## מעבר ל-Supabase

המערכת כבר עובדת על PostgreSQL. פותחים פרויקט ב-Supabase, מעתיקים את מחרוזת החיבור ושמים אותה ב-`DATABASE_URL` (ב-Render: Environment של השירות bakara). בפריסה הבאה הטבלאות נוצרות לבד.
